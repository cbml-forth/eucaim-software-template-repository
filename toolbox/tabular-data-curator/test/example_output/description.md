# Example test case

`test/example_input/` is a small, synthetic and non-confidential dataset in the EUCAIM CDM file
structure: a `clinical_mandatory_view.csv` with 30 synthetic patients, using the same columns and CDM
codes as the `cdm_federated_unbalance_checker` example. It is generated by
`test/generate_example_input.py` (fixed seed). It has a few deliberately injected data-quality
issues, so every TDC check has something to report:

| Feature | Injected issue | Expected TDC result |
|---|---|---|
| `cancer_condition_age_at_diagnosis` | 2 missing values, 1 implausible value (210) | state `fair`, outliers `yes` |
| `first_treatment_type` | 5 missing values (17%) | state `fair` |
| `patient_ethnicity` | 24 missing values (80%) | state `bad`, removed from the clean curated dataset |
| `evidence_procedure_code` | 2 codes without their `CLIN` prefix (numeric) | incompatibility `yes, unknown type of data` |

Categorical features with missing values are also reported as `unknown type of data`, because TDC
cannot infer a single type for them. The similarity reports are empty: the CDM view has only one
numeric feature and no lexically similar feature names.

The reference outputs were produced with the CWL defaults (the image ENTRYPOINT is the CWL
`baseCommand`, `python3 /app/main.py`, so only the CLI flags are passed):

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -v $(pwd)/test/example_input:/app/input_data:ro \
  -v $(pwd)/test/example_output:/app/output_data \
  harbor.eucaim.cancerimage.eu/processing-tools/tdc-app:1.2 \
  -i /app/input_data -o /app/output_data \
  --outlier-method 1 --similarity-method 1 --imputation-method 1
```

# Notes on expected output determinism

Re-running the tool on the example input reproduces the content of every generated report, with
these exceptions:

* `clinical_mandatory_view_results.json` contains a top-level `"timestamp"` field (ISO 8601,
  generation time) that differs on every run. All other fields are deterministic.
* Each `.xlsx` report embeds a document-creation timestamp in its internal `docProps/core.xml`
  metadata (written by `openpyxl`/`xlutils`), which differs on every run. The actual sheet contents
  (cell values, formatting, highlighted cells) are identical across runs.

When validating integration, compare `clinical_mandatory_view_results.json` ignoring the
`timestamp` field, and compare the `.xlsx` files by sheet content rather than by raw file bytes.
